Fixes the VPN upload/test/save/activate workflow and API-SPORTS schedule requests.

- Fix the first-use VPN status error that returned an HTML error page instead of JSON. Unexpected HTTP responses now show a readable error.
- After a successful WireGuard connection test, save the verified configuration in a private Docker volume and queue activation. Saved configuration remains available after app restarts and updates; unverified uploads remain temporary.
- Support explicitly selected host helpers for production port 9999 as well as the isolated 9998 test instance. Preserve the selected instance's data, published ports, and managed VPN Compose graph.
- Automatically list API-covered sports selections, including NBA, NHL, AHL, ECHL, SPHL, FPHL, and NCAA Football. Discover additional covered basketball, hockey, and volleyball competitions from API-SPORTS' catalogues; keep provider/EPG matching for uncovered competitions.
- Request basketball and hockey schedules by date and filter leagues locally, reusing the existing American Football approach. This avoids the league/season request errors seen with the tested free API key. Coverage still depends on the account and API response.
- Refresh schedules, cross-reference provider streams, and rebuild sports channels in one update. Show readable API errors and distinguish successful empty schedules from failed requests.
- Add Settings → Streams with connection modes, client addresses, measured transfer rates, and CPU/GPU/RAM usage when available.
- Add Settings → Open Source & Credits with bundled dependency notices and installer license information.

Validation: the 9999 deployment retained its 54 selected channels and connected VPN, refreshed all nine configured API datasets, and rebuilt 34 sports channels. Port 9998 and the existing VPN sidecar were not restarted. One rate-limited FPHL request succeeded on a subsequent cache-aware retry.

**VPN development preview:** automatic tests, activation, and interactive power switching require the separately running host test worker and connection manager. Packaged installers do not yet provision or supervise these helpers. An already applied VPN uses Docker/Gluetun restart policies; full host reboot coverage, helper supervision, additional providers, and replacement of an active profile remain pending. See [VPN development notes](https://github.com/zschmook/m3u-web-picker/blob/v43/docs/VPN-DEVELOPMENT.md).
