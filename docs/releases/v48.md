# v48 — Guide and playback reliability

- Live Roku/Cast stream startup gets a 30-second budget shared across source attempts. The Roku startup buffer uses the remaining time instead of starting another timeout. This lets slower channels finish opening without multiplying the wait for each fallback.
- Concurrent event-logo requests publish through separate temporary files, preventing requests from replacing or removing one another's in-progress cache writes. Failed writes preserve the previous cache entry and clean up their temporary file.
- Failed health probes remain advisory: saved channels stay in the lineup and can be selected again, with browser labels showing the last probe result.
- Browser and Roku sports maps reuse the saved lineup and stable generated-feed identities. Large Roku guides build only visible rows and keep expensive grouping and layout work off the render thread.
- Provider movie playback retains its paused timeline. Movie-lighting controls support the configured playing/paused behavior and sports settings.
- Preserve the latest main-branch Plex scan counts, SQLite connection cleanup, local-image VPN helper compatibility, and file-backed VPN relay handling.
- Release checks install pinned browser/Roku development tools, run the portable JavaScript suite, validate BrightScript/SceneGraph components, and exercise event-logo concurrency inside the built image. Local dependency folders, runtime data, and copied checkouts are excluded from the build context.

The VPN remains a development preview. Packaged installers bundle and supervise its host helpers; fresh-machine/reboot and additional-provider acceptance testing remain outstanding. The Xbox app remains a separate proposal and is not included as an implemented feature.
